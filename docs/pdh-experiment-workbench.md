# PDH 实验工作台

本工作台面向理解 PDH 原理、但不熟悉当前装置的操作者。入口为左侧 **PDH**，
也可双击画布中的 PDH 状态机。重复打开会复用同一标签页，标签仍可拖出为独立窗口。

## 第一次使用

1. **确认接线**：填写实验方案名称、探测器物理来源、判锁/误差/扫描链及执行器范围。
   系统展示画布的实际相邻连接，点击“查看实际连接”定位节点。连线成立只是本地事实，
   不表示已下载到 FPGA，更不表示物理接线正确。
2. **确认极性**：现有固件按信号**低于**阈值入锁。需要在 PDHS 输入处看到共振谷。
   不能根据“功率”端口名假定它一定是透射信号；峰值输入需先核对反相或变换链。
3. **确认单位**：时钟填实际 PDH 内核时钟，不是示波器采样率。未知留空；此时保持旧周期值，
   禁止 μs 编辑。选填的单位/码标定要求涵盖完整信号链增益且零偏已校正，不能仅套 ADC 量程。
4. **扫描找共振**：从示波器观察、导入 CSV，或用“演示练习”熟悉交互。演示不会产生设备信号。
5. **设置条件**：在波形空白处拖选共振区域；拖红线调入锁阈值、拖青线调失锁阈值。
   确认内核时钟后，可拖图下时间柄或输入 μs。所有编辑先进入草稿。
6. **启动与观察**：解决检查项，核对草稿后明确执行写入。串口离线时仅能保存本地画布。
   启动、退出是单独操作；选择模式、拖线、载入方案不发控制请求。

## 模式的含义

- **手动锁定模式**：手动确定阈值与持续时间，由原状态机执行扫描捕获。
  低于入锁线持续达到条件后接入反馈；高于失锁线持续达到条件后退出。
- **自动锁定模式**：使用已有自动扫描测量生成阈值和时间。主界面只编辑阈值范围位置（%）。
  手动阈值图在此模式为只读参考，不能当作自动实际阈值。没有自动测量结果回读时不捏造结果。
- 两种模式均**不等于自动 PID 整定或自动重锁**。当前 `00` 是请求，不是所有状态下的可靠急停。
  退出锁定、暂停扫描、执行器归零是不同动作。

## 三种独立的确认

| 显示 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 本地配置 / 草稿 | 软件持有这些设置 | FPGA 已应用 |
| 所选参数回读一致 | 写入的寄存器已按值核对 | 内部状态机已启动或锁定 |
| 离线判据预演 | 采样数据按手动判据预计发生的切换 | 硬件实际事件或稳定光学锁定 |

固件目前未提供内部状态、自动测量极值/脉宽等回读。运行反馈固定标明此能力缺失，
不由 `pc_cmd` 推断“已锁定”。真实锁定仍需独立观测。

## 波形数据与边界

CSV 表头必须为 `time_s,value`，时间严格递增，value 为到达 PDHS 输入处的有符号 16 位范围内
内部信号码。最多 20,000 点、2 MB；NaN、无限值、重复时间、越界数值会拒绝，旧图保持不变。

```csv
time_s,value
0.000,18000
0.001,15000
0.002,4000
0.003,15000
0.004,18000
```

“从选区生成判据草稿”用选区极值与谷宽提出建议，不是寻找最佳锁点的保证。
手动预演不还原采样间隙内的穿越、FPGA 流水线或精确逐时钟行为。

取示波器 CH1 快照之前，须确认 CH1 对应当前判锁输入及相同内部信号码。
改变信号来源、标定或画布接线后需重新确认；不能把任意示波器信号当作判锁证据。
UDP 快照只采用同一已完成采集的连续存储片段，来源/采样率随批次固定。
Legacy UDP 没有包序号，所以即使点数齐全，也不能证明线路传输无丢包或乱序。
重新导入之前保存的实测快照统一显示为**回放**，不是新的实时数据。

## 保存与兼容

- “保存方案”原子保存 JSON：版本、实验档案、参数草稿、观测来源、波形和选区。
  打开时完整校验后才替换；文件中的 `pc_cmd` 不执行，也不覆盖当前设备请求值。
- 主画布配置仍为原 `version: 1`，PDHS 节点可增加可选 `pdh_experiment` 附属字段。
  不带该字段的旧文件照常使用。
- “记入实验记录”把当前方案、参数快照、数据来源和预演说明保存到现有本地记录仓库。
  含波形样本的可复现实验包另用“保存方案”。
- 保留原 7 个寄存器标识/地址和固定点数据格式。历史 uint32 时长及负 Q1.15 不静默截断；
  新时长写入仍受现有 int31 安全上限约束。工程详情可查原始值。
- 刷新时若有草稿，展示旧基线/新设备值/草稿，显式选择采用设备值或重新核对草稿。

## Agent / MCP

Agent 的 PDHS 节点列表、参数查询和画布快照包含同一实验档案与本地接线诊断。
缓存改变时不会继续沿用旧“设备已读取”标签；这些读取不打开窗口、不触发设备读取。
MCP v1 仍是只读模块目录和离线候选图校验，不提供当前 GUI、波形或设备控制接口。
见 [MCP 启动与验收](local-mcp-server.md)。

## 验证

```sh
python -m unittest discover -s tests -v
DCLOCKING_MCP_BOOTSTRAP_SMOKE=1 python -m unittest discover -s tests -p 'test_mcp*.py'
python scripts/verify-pdh-workbench.py --artifacts /path/to/temp-artifacts --keep-open
```

可视验证脚本使用真实 Qt 窗口和 QTest 键鼠，隔离配置/记录，使用显式演示方案，不连接设备、
不调用 LLM、不读 API 密钥。Windows 通过相同 Python 脚本运行；MCP 原生启动器验收选择 PowerShell。

## 下一阶段硬件能力

此次未修改 VHDL 控制算法、参数 ABI 或总线命令。如下能力不能由软件界面冒充：

- 带版本的当前 FSM 状态、校准极值/脉宽/实际阈值、状态切换原因与时间回读。
- 保留配置的确定性退出确认；现有通用 `.reset()` 会同时复位参数 RAM，不可直接用作此操作。
- 多通道同步数据、完整性序号、已验证的物理量标定。
- 自动重锁或自动整定策略（另行定义与实机验收）。

需要固件接口与真实板卡联调后，才可验收“真实运行阶段显示”和完整闭环锁定结果。
