# DClocking 完整集成界面优化设计

## 1. 背景与目标

DClocking 当前以 PySide6 提供 FPGA 节点编排、串口控制、参数配置、配置保存/恢复及 Agent 辅助设计能力。现有界面功能完整，但控制区、画布、模块列表、参数窗口、日志和 Agent 面板缺少统一的视觉层级，画布也被多个常驻区域挤占。

本次改版参考 `Comb-code` 的深红识别色、仪器控制台结构和高密度工程界面，采用已确认的 **B2「精密仪器工作台 / 画布优先」**方案。目标是：

1. 让信号画布成为主视觉和最大操作区域。
2. 建立一致的工具栏、导航、检查器、状态栏、Agent 和节点视觉系统。
3. 保留现有全部业务行为、硬件协议和配置语义。
4. 明确并验证连线与组件端口之间无可见空档。
5. 同时改善普通 Qt 入口和带 Agent 的集成入口。

## 2. 范围

### 2.1 本次包含

- 主窗口整体布局、尺寸策略、QSS 和主题令牌。
- 顶部设备与配置命令栏。
- 左侧深红导航轨及现有区域快捷入口。
- 中央节点画布背景、节点、端口、连线、选中和悬停状态。
- 右侧模块/参数检查器。
- 底部状态栏和可展开命令日志。
- Agent Dock、聊天消息、输入区、设置入口和按需显示方式。
- 界面几何状态的本地保存与恢复。
- 离线自动化检查、GUI 截图检查和现有功能回归验证。

### 2.2 明确不包含

- 不修改 UART、Bus、FPGA 路由协议或寄存器地址。
- 不修改硬件端口编号、节点内部名称或参数编码。
- 不修改保存配置文件的数据格式和字段语义。
- 不修改 LLM 请求流程、工具 schema、提示词或 CanvasBridge 契约。
- 不新增 FPGA 模块、Qt 节点类型或 Agent 工具。
- 不引入第三方 Qt 组件库或额外字体依赖。
- 不实现新的业务页面；导航轨仅访问现有区域和动作。
- 不采用无边框自定义标题栏，保留 macOS 原生窗口行为。

## 3. 设计原则

### 3.1 视觉壳层与业务逻辑分离

现有对象继续拥有原职责：

- `qt_ui_mainwindow.MainWindow` 继续编排串口、路由、参数、配置和设备同步。
- `qt_ui_graph.DiagramScene/DiagramView` 继续处理节点和边的图形交互。
- `qt_module.NodeItem` 及子类继续拥有节点身份、端口和参数模型。
- `AgentChatWidget → AgentCore → ToolExecutor → CanvasBridge` 调用链不变。

新增主题、布局辅助组件和显示动作只调用现有公开行为，不复制业务实现，也不让 Graph 层依赖 MainWindow 或 Agent。

### 3.2 画布优先

- Agent 默认收起。
- 命令日志默认折叠为状态栏。
- 右侧检查器维持满足参数操作的最小宽度，画布取得剩余空间。
- 主区域和日志区域使用可调 `QSplitter`，不再依赖固定高度堆叠。

### 3.3 语义化颜色

深红只承担品牌、选中和主操作；信号颜色、连接状态和错误状态保持独立语义。不能为了统一配色而把不同信号类型改成同一种颜色。

## 4. 信息架构与布局

```text
QMainWindow（保留原生标题栏）
└─ CentralWidget
   ├─ LeftRail：品牌与现有区域快捷入口
   └─ MainColumn
      ├─ CommandBar：串口、模式、连接、初始化、保存、加载、清空、Agent
      ├─ VerticalSplitter
      │  ├─ HorizontalSplitter
      │  │  ├─ DiagramView：节点画布
      │  │  └─ Inspector：模块列表 + 参数面板
      │  └─ LogPanel：默认折叠、按需展开
      └─ StatusBar：连接、模式、路由、配置和日志状态

QMainWindow.RightDockWidgetArea
└─ AgentChatWidget：默认隐藏，可停靠、浮动、关闭和恢复
```

### 4.1 左侧导航轨

导航轨宽度约 56–64 px，使用 `#85172E` 背景和竖排 `DCLOCKING` 字标。入口只映射现有能力：

- 设计：聚焦画布并收起 Agent。
- 参数：聚焦右侧检查器。
- 配置：弹出保存/加载菜单，复用现有保存和加载动作。
- 日志：展开或收起命令日志。
- 设置：仅在 Agent 集成入口存在时打开 Agent 设置；普通入口隐藏该入口。

所有图标按钮必须有 tooltip、accessible name 和键盘焦点状态。当前选中项除颜色外还使用白色容器或边框，避免只依赖颜色表达状态。

### 4.2 顶部命令栏

命令栏紧凑排列现有控件：

1. 串口选择。
2. Free/Developer Mode。
3. 连接设备主按钮。
4. 初始化按钮。
5. 保存配置。
6. 加载配置。
7. 清空画布。
8. Agent 显示切换（仅集成入口）。

控件继续复用 `comboBox`、`mode_combo`、`connect_btn`、`init_btn`、`save_cfg_btn`、`load_cfg_btn` 和 `clear_btn`，已有信号连接保持不变。按钮文案、启用状态和现有槽函数不得因换皮而改变语义。

### 4.3 中央画布

画布使用 `#171B1D`，叠加低对比度点阵网格。左上角可显示纯展示信息，例如缩放比例和当前路由数；不得把展示标签作为业务状态的第二事实源。

画布保留：

- 节点拖放和跨 palette 移动。
- Ctrl + 滚轮缩放。
- 视图平移。
- 节点选择和删除。
- 输入单连接和输出 fan-out。
- Free/Developer Mode 的信号兼容规则。
- 正向、反向、绕行和并行 lane 路由。
- 画布边界输入/输出端口。

### 4.4 右侧检查器

右侧常驻单一检查器，默认宽度约 260–340 px，通过 `QSplitter` 可调整。它包含：

- 模块列表及分类标题。
- 模块搜索框；只过滤 palette 的显示，不改变模块工厂。
- 当前选中节点摘要。
- 已有参数面板容器、参数应用和清空操作。
- 可选的路由摘要标签页；第一阶段只读取现有画布状态，不新增路由模型。

参数提交继续走 `set_param_apply_handler(MainWindow._apply_param_to_hardware)`，stage/commit/rollback 和 readback 行为不变。

### 4.5 日志与状态栏

命令日志改为可折叠区域：

- 默认只显示 30–36 px 状态栏。
- 用户展开后恢复可调日志高度。
- 普通 stdout 不强制展开。
- stderr、串口失败、路由失败、参数下发失败和配置加载失败时自动展开，并保留原始错误文本。
- 日志仍限制最大 block 数，避免长期运行持续增长。

状态栏显示现有状态的只读摘要：连接/离线、当前模式、路由数量、配置是否已修改和日志开关。若当前代码没有可靠的“配置已修改”信号，则第一阶段不展示该项，不能通过猜测构造状态。

### 4.6 Agent 按需抽屉

`AgentChatWidget` 保持 `QDockWidget`：

- 集成入口创建后默认隐藏。
- 顶部 Agent 按钮、右下角 AI 浮动按钮和 `toggleViewAction()` 绑定同一个可见状态。
- 关闭 Dock 只隐藏，不销毁 AgentCore、消息列表或会话状态。
- 再次打开恢复原停靠位置和宽度。
- 浮动与重新停靠沿用 Qt 原生行为。
- 普通入口不显示空的 Agent 控件。

MainWindow 提供轻量注册方法接收可选 Dock 或 QAction；`FPGA_Agent/main.py` 完成装配。MainWindow 不 import Agent 包。

## 5. 视觉系统

### 5.1 色板

| 令牌 | 色值 | 用途 |
|---|---|---|
| `PKU_WINE` | `#85172E` | 导航轨、主操作、选中强调 |
| `PKU_WINE_HOVER` | `#9C2942` | 深红控件 hover |
| `CANVAS_BG` | `#171B1D` | 画布背景 |
| `NODE_BG` | `#272D30` | 节点主体 |
| `NODE_HEADER` | `#31383B` | 节点标题区 |
| `SURFACE` | `#FBFBF9` | 命令栏、检查器、对话框 |
| `SURFACE_MUTED` | `#EDECE8` | 次级表面和原生标题栏衔接 |
| `BORDER` | `#DEDBD5` | 浅色面板分隔线 |
| `SIGNAL_ACCENT` | `#E1A644` | 视觉稿示例信号，不覆盖现有动态信号色 |
| `READY` | `#35A475` | 在线/成功状态 |
| `ERROR` | `#D2556E` | 错误状态和选中强化 |

实际连线继续由 `PortItem.line_color` 决定。上表中的信号色只作为默认/示例令牌，不统一替换 `COLOR_POOL`。

### 5.2 字体

- 界面正文：`Helvetica Neue`，中文回退 `PingFang SC`。
- 数值、状态和日志：`Menlo`，回退系统等宽字体。
- 不下载或打包新字体。
- 正文不低于 12 px；紧凑状态文本不低于 10 px。

### 5.3 控件形态

- 圆角集中在 6–9 px，不使用大面积胶囊形控件。
- 不使用 Comb-code 旧式渐变按钮；保持扁平、清晰的工程工具风格。
- 主按钮为深红实底；次按钮为浅色表面加边框。
- hover、pressed、disabled、focus-visible 状态均有独立表现。
- 分隔主要依靠边框、间距和表面层级，不堆叠阴影。

### 5.4 节点与端口

- 节点主体使用 `NODE_BG`，标题区使用 `NODE_HEADER`。
- 标题左侧有窄深红识别条，右侧显示内部身份缩写。
- 选中节点使用边框与外描边，不改变内部名称或端口位置。
- 端口圆点保留输入/输出和信号类型语义；端口仍位于节点边缘中心。
- 节点尺寸只在现有自适应规则范围内调整，不能导致端口索引或连线语义改变。

## 6. 连线连续性约束

这是本次改版的强制验收项。

### 6.1 几何规则

1. 每条 `EdgeItem` 的路径首点必须等于 `start_port.scenePos()`。
2. 路径末点必须等于 `end_port.scenePos()`。
3. 临时拖拽线在悬停合法目标时，末点使用目标端口的 `scenePos()`。
4. 笔画必须在端口圆点下方延伸到圆心，由端口圆点覆盖线端，形成 1–2 px 的视觉重叠。
5. 不绘制独立的悬空终点圆点；唯一的端点标识是实际端口。
6. Z 顺序保持“节点/端口在上、连线在下”，但连线不能在组件边缘外提前终止。

### 6.2 全路径适用

上述规则必须覆盖：

- 普通左右连接。
- 输出 fan-out。
- 反向连接。
- 上下绕行。
- sibling lane 偏移。
- 节点移动后的 `update_path()`。
- 缩放、平移和 resize 后的显示。
- 画布边界端口到节点端口。

### 6.3 自动化断言

离屏 Qt 测试应读取 `QPainterPath`：

- `elementAt(0)` 与起点端口场景坐标误差不超过 0.01 scene unit。
- 最后一个 path element 与终点端口场景坐标误差不超过 0.01 scene unit。
- 移动节点并调用更新后重复断言。
- 对正向、反向、绕行和 fan-out 各至少覆盖一个场景。

视觉截图还需在 100%、缩小和放大比例下检查端口附近无背景色断裂。

## 7. 状态、错误与空状态

### 7.1 离线状态

- 未连接 FPGA 时明确显示“离线编辑”。
- 画布、节点、配置保存/加载和 Agent 画布操作继续可用。
- 初始化和需要设备的动作保持现有禁用或失败行为，不伪造成功状态。

### 7.2 错误反馈

- 串口、路由、参数和配置错误继续输出完整技术信息到日志。
- 状态栏只展示短摘要和错误色，不替代日志详情。
- 参数失败继续 rollback 本地缓存并尽量 readback。
- 加载部分失败不能显示“成功完成”。
- Agent 工具失败继续以现有 tool/system message 呈现，同时不得阻塞 GUI 线程。

### 7.3 空状态

- 空画布提供简短操作提示，例如从右侧模块列表拖入组件或打开 Agent。
- 空参数区说明需选择节点，不显示无意义的空白表单。
- 无 Agent 的普通入口不展示不可用的 AI 按钮。

## 8. 状态持久化

使用 `QSettings` 保存纯界面状态：

- 主窗口 geometry/state。
- 主区域与检查器 splitter sizes。
- 日志展开状态和上次展开高度。
- Agent Dock 可见性、停靠区域和宽度。

这些状态不写入 DClocking 的 FPGA 配置 JSON，也不改变 `save_configuration/load_configuration` 格式。若保存状态缺失或版本不兼容，则回退到 B2 默认布局，不阻止程序启动。

## 9. 实现边界与文件职责

预计改动集中在：

- `python control/qt_ui_theme.py`：新增视觉令牌、字体、主窗口 QSS 和图标辅助。
- `python control/qt_ui_mainwindow.py`：重组视觉布局、导航、状态栏、日志折叠和可选 Agent Dock 注册。
- `python control/qt_ui_graph.py`：画布、palette、边界端口、连线和拖拽缩略图样式；保持图模型不变。
- `python control/qt_module.py`：提取复用的节点视觉绘制辅助，替换重复硬编码外观；不改 schema 和身份映射。
- `FPGA_Agent/chat_styles.py`：使聊天样式采用同一主题。
- `FPGA_Agent/agent_chat_widget.py`：调整布局、可访问名称和公开设置入口；保持消息 API 与信号不变。
- `FPGA_Agent/main.py`：注册 Agent Dock 和显示动作，其他装配链不变。

若实现过程中发现某项视觉需求必须改变节点身份、配置格式、硬件映射或 Agent 工具契约，必须停止并单独进行跨层设计，不在本改版中顺带修改。

## 10. 验证策略

### 10.1 自动化离线验证

使用 `QT_QPA_PLATFORM=offscreen`：

- 两个入口模块可 import，窗口可构造和关闭。
- 主题模块没有第三方依赖，令牌格式有效。
- 主布局包含命令栏、画布、检查器、状态栏和可折叠日志。
- 普通入口不显示 Agent 控件；注册 Agent Dock 后两个入口可控制同一可见状态。
- 日志展开/折叠不丢失文本。
- 节点创建、移动、删除和实例索引回收不变。
- 连线几何执行第 6.3 节全部断言。
- 参数面板仍调用原 handler；失败仍 rollback。
- 配置保存→清空→加载保持相同节点、direct 参数和边。

### 10.2 GUI 交互验证

启动 `FPGA_Agent/main.py` 和 `python control/qt_UI1.py`，分别检查：

- 1280×720、1600×900 和高分屏缩放。
- splitter 拖动、状态恢复和最小尺寸。
- palette 拖放、节点选择、连线、断开和 fan-out。
- Agent 打开、关闭、浮动、重新停靠及消息保持。
- 日志自动展开和手动折叠。
- 键盘焦点、tooltip、文本截断和滚动行为。

### 10.3 在线与硬件验证

具备设备时再验证：

- 串口扫描、连接、初始化和断开。
- 画布路由 upload 和断开写入 VOID/VOID_BOOL。
- 参数提交、失败回滚和 readback。
- `sync_from_device` 重建节点、参数和连接。

没有 FPGA 时必须明确标记这些项目未验证，不以离线 UI 测试替代硬件结论。

## 11. 完成标准

满足以下条件才可认为界面优化完成：

1. B2 布局和已确认色板在普通入口与 Agent 入口一致呈现。
2. 画布、右侧检查器、日志和 Agent 均可调整或按需显示。
3. 所有现有业务动作仍绑定原实现，配置格式与硬件契约无变化。
4. 所有连线路径在组件移动和各种绕行场景下都覆盖端口圆心，无可见空档。
5. 离屏回归测试通过，三种目标尺寸截图无重叠、裁切或不可访问控件。
6. 无硬件环境下的未验证项被明确列出；不宣称 FPGA 在线行为已经验证。
